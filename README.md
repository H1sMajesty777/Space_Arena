# SPACE ARENA

## Структура проекта

- `frontend/` — публичный сайт, заказ и панель бара на React. Vite собирает все три страницы, общие стили и изображения.
- `frontend/src/features/public-site/` — компоненты главной, публичного меню, тарифов и их данные.
- `frontend/public/assets/` — общие изображения, доступные по `/assets/`.
- `backend/` — FastAPI и модели базы данных.
- `banner/` — исходники анимированного баннера.
- `demo/` — локальный просмотр баннера на скриншоте рабочего стола.
- `agent/` — Windows-агент и готовый архив для установки на клубные ПК.
- `deploy/` — конфигурации Nginx и настройка доступа по локальной сети.
- `scripts/` — проверки и синхронизация меню; `docs/` — отчёт о реализации.
- Файлы `docker-compose*.yml` и `.env` остаются в корне для запуска Docker.

Зависимости JavaScript не хранятся в проекте. Для локальной разработки установите их командами `npm ci --prefix frontend` и `pnpm install --dir banner`. При сборке Docker зависимости фронтенда устанавливаются автоматически.

Для работы над публичной страницей запустите `npm run dev --prefix frontend` и откройте http://127.0.0.1:5173/. Команда `npm run build --prefix frontend` также создаёт `frontend/dist/standalone.html`, который можно открыть с диска.

### Тема сайта

Из корня проекта выполните `node scripts/site-theme.mjs winter` для праздничной темы или `node scripts/site-theme.mjs classic` для обычной. Команда без аргумента показывает текущую тему. Выбор применяется к главной, публичному меню, гостевым заказам и панели бара после обновления страницы.

После первого обновления проекта пересоберите только веб-контейнер командой `docker compose up -d --build --no-deps web`. Дальнейшие переключения темы берутся с диска и сохраняются при перезапуске контейнеров. Для отдельного файла `standalone.html` тема выбирается при сборке. Стили тем находятся в `frontend/src/styles/classic.css` и `frontend/src/styles/winter.css`.

## Локальный запуск

Запустите Docker Desktop, затем `Start-SpaceArena.bat` или `docker compose up -d --build --wait`.

- Публичный сайт — http://localhost:8080/
- Панель бара — http://localhost:8080/bar.html
- Заказ — http://localhost:8080/order, требуется вход по QR или баннеру агента.
- API — http://localhost:8000/docs (доступен только с сервера).

Учётные данные администратора находятся в `.env`. При первом запуске используйте `.env.example` и задайте уникальные пароли. Пароль существующего администратора изменение `.env` не заменяет.

## Подключение компьютера

1. В панели бара откройте «Столики · QR» и подключите ПК к нужному месту. Столы 42–46 в Space Room, места TV1–TV5 и столы из старых заказов добавляются автоматически. Для других мест выберите название или введите номер стола.
2. Скопируйте папку `agent` на игровой компьютер.
3. Запустите `agent/Install.bat`. Он подготовит Python и зависимости, создаст ярлык автозапуска для текущего пользователя Windows и откроет баннер. Для запуска без регистрации автозапуска используйте `agent/Start.bat`.
4. Введите адрес сервера и одноразовый код из админки. Код действует 10 минут и используется один раз.
5. Агент сохранит секрет через Windows DPAPI и откроет баннер с QR справа сверху. Отступы выравнивают его по верхней линии логотипа и правому краю OTHER; нижний край совпадает с рамкой GAMES на клубных обоях.

Для проверки на этом компьютере используйте `http://localhost:8080`. Для теста по Wi-Fi задайте PUBLIC_ORIGIN=http://IP-компьютера:8080 и ALLOW_INSECURE_LOCAL=true. Агент принимает локальный IP с портом. Телефон подключите к той же сети. В размещённой системе используйте HTTPS.

Баннер находится ниже обычных окон и не появляется на панели задач. Клик по нему открывает меню в обычном браузере. Чтобы выключить баннер и автоматическое восстановление, запустите `agent/Stop.bat`. Чтобы включить, запустите `agent/Start.bat`. Для повторной настройки сначала выключите баннер, затем запустите `agent/Configure.bat`. После установки не перемещайте папку агента, иначе ярлык автозагрузки потребуется создать повторно.

Чтобы посмотреть расположение и анимацию баннера без запуска агента, откройте `demo/Open-Demo.bat`. Страница использует скриншот рабочего стола и демонстрационный QR, поэтому заказ в ней не оформляется. Клавиша `R` повторяет анимацию.

Администратор может отключить стол/ПК и заменить секрет. При замене секрета в админке появляется новый одноразовый код. Для расчёта и сброса гостевого доступа используется вкладка «Карта клуба».

## Карта клуба и оплата

На карте два этажа. Зелёное место свободно от открытых счетов и отметок. Красный появляется при неоплаченном заказе или ручной отметке сотрудника. «Выдан» означает, что заказ доставлен, поэтому место остаётся красным до расчёта. Отменённые заказы исключаются из счёта. Столы вне плана показаны под схемой.

Space Room отображается одной комнатой и подсвечивается, пока у любого её места есть открытый счёт или ручная отметка. Нажмите на комнату, чтобы выбрать стол. В заказе бармен видит конкретный номер, а при расчёте закрывается счёт только выбранного стола.

После получения оплаты нажмите на место, сверьте заказы и сумму, затем выберите «Оплата получена · Закрыть счёт». Если за это время пришёл или отменился заказ, панель обновит счёт и попросит подтвердить его снова. Закрытие очищает гостевую историю и корзины всех ПК этого места, отзывает старые ссылки и сессии. Агент выдаст новый QR после очередной проверки связи. В панели бара заказ сохраняется с отметкой об оплате, а кухня продолжает работу с его текущим статусом.

Для заказа вне сайта можно отметить место вручную, а после оплаты закрыть счёт. Ошибочную отметку можно снять. Кнопка закрытия доступна при открытом счёте или ручной отметке.

При первом обновлении выданные более 15 минут назад заказы без действующего визита остаются в истории бара без отметки об оплате. Они не входят в новый счёт. Незавершённые заказы и заказы действующих визитов нужно сверить при расчёте.

## Доступ и данные

Агент получает QR заранее. Срок QR — 20 минут, обновление за минуту до окончания. Агент проверяет доступ каждые 30 секунд. При отключении или ошибке связи он скрывает QR и показывает сообщение. Блокировка на сервере применяется при каждом запросе.

Баннер и QR одного клубного ПК открывают общий визит. Сервер выдаёт каждому браузеру свою HttpOnly cookie и перенаправляет на `/order`. Визит длится до 3 часов с первого входа. Телефон и ПК видят одну историю и корзину, в том числе после обновления QR. Разные ПК за одним столом ведут отдельные визиты.

После обновления со старой версии откройте свежий QR на каждом устройстве. Заказы из действовавших сессий этого ПК подтянутся к общему визиту. Корзины старой версии хранились в отдельных браузерах.

PostgreSQL хранит столы, ПК, хэши секретов и заказы со временем выдачи и оплаты. Redis хранит хэши ключей QR и сессий, TTL, счётчики сканов и ограничения частоты запросов. AOF и Docker-том Redis включены. При потере данных Redis потребуется повторный вход по QR, заказы доступны персоналу в PostgreSQL. Истёкшие временные записи Redis удаляет автоматически.

История и корзина обновляются каждые 5 секунд в активной вкладке. Выданные заказы остаются в истории гостя до закрытия стола или окончания срока доступа. Окончание срока доступа не закрывает счёт.

Мобильный интернет поддерживается через публичный HTTPS-адрес. Любой браузер, открывший действующий QR этого ПК, входит в его текущий визит.

## HTTPS при размещении

Задайте в `.env` `PUBLIC_ORIGIN=https://ваш-домен`, `ALLOW_INSECURE_LOCAL=false`, соответствующий `CORS_ORIGINS`. Положите сертификат и ключ в `tls/fullchain.pem` и `tls/privkey.pem`. Эти файлы не добавляйте в Git.

Запуск — `docker compose -f docker-compose.yml -f docker-compose.production.yml up -d --build --wait`.

Production override публикует только HTTPS-порт 443 веб-сервера и закрывает публикацию API. Продление сертификата выполняется инфраструктурой хостинга. В nginx адрес клиента перезаписывается перед передачей в API. `/order` исключён из access log, access log Uvicorn выключен, ответы API и страницы входа имеют `no-store` и `no-referrer`.

## Проверка

`docker compose -p spacearenafrontendcheck -f docker-compose.yml -f docker-compose.preview.yml up -d --build --wait`

`node scripts/check-access.mjs`

Проверка использует отдельные Docker-тома и создаёт тестовые столы, ПК и заказы. После проверки остановите этот стек той же командой compose с `stop`.

Основные файлы — `backend/app/routers/access.py`, `orders.py`, `models.py`, `bootstrap.py`, `frontend/src/pages/OrderPage.jsx`, `frontend/src/components/admin/TableAccess.jsx`, `agent/agent.py`, `deploy/nginx.conf`.

Для остановки рабочего проекта используйте `docker compose stop`. Данные и фотографии сохраняются в Docker-томах.

## Текущая проверка с телефона по Wi-Fi

Для проверки по локальной сети укажите LAN-адрес сервера в `PUBLIC_ORIGIN`. Телефон должен быть в той же Wi-Fi-сети. Если доступ блокирует Windows Firewall, запустите `deploy/Allow-LAN.bat` на сервере и подтвердите UAC. Правило открывает порт 8080 для локальной подсети в профиле Private.

Перед обновлением с версии с автоматическим восстановлением запустите `agent/Stop.bat`. Для более ранней версии завершите `pythonw.exe` с аргументом `agent.py` через Диспетчер задач. После замены файлов запустите `agent/Install.bat`, чтобы обновить ярлык автозапуска и запустить баннер. Для нового подключения укажите LAN-адрес сервера с портом 8080. При смене IP обновите `PUBLIC_ORIGIN` в `.env` и пересоздайте контейнер API.
