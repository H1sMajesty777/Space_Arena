# Отчёт о реализации доступа SPACE ARENA

Дата — 13 ноября 2026.

## Результат

Добавлен доступ к заказу через Windows-агент и временный QR. Баннер и QR используют один адрес `/order?table=…&t=…`. После входа сервер выдаёт гостевую cookie и перенаправляет на `/order`. Публичный сайт доступен без авторизации.

Старый допуск через номер ПК, заголовок гостя и JWT QR заменён новым входом. Номер стола для заказа выбирается сервером из сессии. Попытка передать `table_number` в теле заказа отклоняется.

## Выполненные части

- PostgreSQL — таблицы `tables`, `pcs`, хэши секретов, версия отзыва доступа, время последней связи. В `orders` добавлены `table_id`, `session_id`, `served_at`. Миграция переносит номера столов из существующих заказов.
- Redis — QR на 20 минут, гостевые сессии на 3 часа, счётчики сканирований и rate limiting. Ключи QR, сессий и подключения хэшируются. Истёкшие записи удаляются через TTL.
- Авторизация — HttpOnly cookie, SameSite=Lax, Secure при HTTPS. Защита POST заказа по Origin. При недоступном Redis API возвращает 503.
- QR многоразовый, обновление не завершает действующие сессии. Повторный вход на тот же стол сохраняет действующую сессию без продления срока.
- Блокировка стола/ПК отзывает токены и сессии по версии доступа. Повторное включение не возвращает ранее отозванный доступ.
- Админка — создание столов и ПК, включение/отключение, замена секрета, время последней связи.
- Постоянный секрет выдаётся агенту при обмене одноразового кода подключения, который действует 10 минут. Постоянный секрет не возвращается интерфейсу администратора и не используется в URL.
- Windows-агент — шифрование настроек DPAPI текущего пользователя, QR и баннер, обновление за минуту до истечения, проверка блокировки каждые 30 секунд, скрытие QR при ошибке связи, повторные подключения, установщик окружения и ярлыка автозапуска.
- Гостевой frontend — сессия через cookie, автообновление через 5 секунд, изоляция истории по сессии и столу.
- Через 15 минут после выдачи заказ исчезает из гостевой истории. Персоналу история доступна. Повторное присвоение статуса не сбрасывает отсчёт.
- Nginx — защищённая выдача HTML заказа через internal location, no-store, no-referrer, перезапись X-Forwarded-For, отключение логов URL входа. Uvicorn access log отключён.
- HTTPS — отдельный production override с портом 443 и подключением сертификатов. В production порт API наружу не публикуется.

## Проверки

На отдельном Docker-стеке выполнен `node scripts/check-access.mjs`. Проверены одноразовое подключение агента, повторный скан QR, неверный стол, вход без сессии, cookie, защита Origin, отклонение подмены стола в заказе, изоляция двух гостей одного стола и гостей разных столов, сохранение сессии после выпуска нового QR, недействующий QR, статус выдачи и скрытие через 15 минут, доступ персонала к скрытому заказу, блокировка ПК, heartbeat, замена секрета. Проверено отсутствие проверяемых device_secret и temp_token в логах API и nginx.

Истечение QR воспроизведено принудительным истечением ключа Redis. Для проверки 15 минут использовано изменение `served_at` тестового заказа на 16 минут назад. Полные 20 минут по часам в этой проверке не ожидались.

Сборка React прошла. Python-файлы проверены компиляцией. На Windows установлены зависимости агента и выполнена проверка шифрования/расшифрования DPAPI и создания QR. Дополнительно агент прошёл подключение к тестовому API, обмен одноразового кода, сохранение и повторное чтение зашифрованных настроек, получение QR и отрисовку в скрытом окне Tk.

## Границы проверки

Интерактивный интерфейс Windows-агента, запуск через установленный ярлык после входа в Windows и сканирование камерой телефона пока не проверялись. Проверка через LTE и настоящий HTTPS-домен потребует адреса сервера и сертификата. Production-конфигурация подготовлена, публичный сервер не развёрнут.

Текущая локальная конфигурация допускает HTTP на localhost с `ALLOW_INSECURE_LOCAL=true`, порты привязаны к loopback. Для размещения используется HTTPS и `ALLOW_INSECURE_LOCAL=false`.

QR можно переслать до истечения срока. На общем ПК сессия истекает автоматически через 3 часа, момент смены игрока система без внешнего сигнала не определяет. Выданные заказы скрываются через согласованные 15 минут. Потеря временных данных Redis требует повторного входа по QR.

## Как посмотреть

1. Открыть http://localhost:8080/bar.html и войти с данными из `.env`.
2. В разделе «Столики · QR» добавить ПК для нужного стола и получить одноразовый код.
3. Запустить `agent/Install.bat`, указать `http://localhost:8080` и код подключения.
4. Нажать баннер агента. Страница заказа откроется с привязкой к столу.

Подробная настройка и команды размещения находятся в `README.md`.

## Исправление локального доступа

Для внутреннего маршрута /_guest_page явно задан MIME text/html. Автоматическая проверка подтверждает Content-Type и HTML после входа с cookie. Добавлен HTTP-доступ по частному IP для режима разработки, QR направлен на 192.168.0.134:8080. Адрес /health доступен с компьютера по LAN-IP. Проверка с реального телефона остаётся за пользователем. Windows отказала в добавлении firewall-правила без административных прав; подготовлен Allow-LAN.bat с UAC. Перезапуск агента из среды отклонён автоматической защитой, нужен ручной запуск Start.bat после завершения текущего агента.
